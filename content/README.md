# 每日推荐内容

每天保存一个 `YYYY-MM-DD.json` 文件，日期为推荐日期（Asia/Singapore）。文件长期保留；网站构建只读取最近 7 个自然日，缺少某天时不拿更早内容补位。同一天修正时修改同一个文件，Git 保存修改历史。

每次填写前读取根目录 `site.config.json` 中的方向 ID，按下表填写。未知字段、未知方向、日期矛盾、重复论文或无法渲染的公式会使构建报错。修正并重新构建，通过后才能发布。

| 字段 | 含义 |
| --- | --- |
| `date` | 推荐日期，必须与文件名一致 |
| `status` | `complete`：当天筛选完成；`incomplete`：仍有入口或筛选未完成 |
| `frontiers_status` | `recommendations`：优化前沿有推荐；`no_matches`：已筛选但无合适推荐；`incomplete`：优化前沿未完成，可保留已核实论文 |
| `papers` | 论文数组，同一论文只填写一次，可以有多个方向 |

每篇论文包含：

| 字段 | 填写方式 |
| --- | --- |
| `arxiv_id`、`version` | 不含版本号的 ID，以及整数版本号 |
| `title`、`authors` | 原文英文标题；作者姓名数组 |
| `submitted`、`updated` | 原文首次提交、当前版本更新日期，格式 `YYYY-MM-DD` |
| `directions` | 方向 ID 数组，不填写自由命名的新标签 |
| `arxiv_url` | `https://arxiv.org/abs/` 后接对应 ID，可包含匹配的版本号 |
| `abstract` | 原文英文摘要 |
| `summary`、`reason` | 中文 Summary、具体推荐理由 |
| `order` | 正整数阅读顺序，当天不能重复 |
| `update_note` | 可选；已推荐论文因实质更新再次入选时必须说明变化 |

文字使用纯文本，不填 HTML。公式支持 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`。JSON 中的反斜杠需要双写，例如 `"$\\nabla f(x)$"`；普通美元符号写作 `"\\$"`。不要为通过公式检查修改论文结论，应核实原文写法。

Summary 不设固定句数或字数，沿一条清楚的主线说明研究问题与现有困难、关键方法、主要结果、重要成立条件，以及相对已有工作的关键区别或实质进展。进入论文特有贡献时须明确归属，随后可用算法、分析、定理或实验自然承接。推荐理由说明最值得阅读的内容及具体依据；对后续研究的启发只在有可靠依据时写，并明确区分论文结论与编辑判断。两部分都先保证准确和逻辑完整，再删除重复信息。

完整填写结构见 [示例文件](../examples/daily.example.json)。示例论文和 ID 仅供排版演示，不是真实推荐，不能复制进本目录发布。

若当天所有筛选完成且没有合适论文，真实记录可以写为：

```json
{
  "date": "2026-09-12",
  "status": "complete",
  "frontiers_status": "no_matches",
  "papers": []
}
```

未完成检索时不能使用上面的空结果冒充完成。尚无当天文件则网页显示尚无日报。

跨天去重还需由执行者读取完整私有推荐历史。构建器只检查本次 7 天窗口内的重复推荐与版本变化，不会重读全部历史归档，也不能替代对“实质更新”的原文判断。
